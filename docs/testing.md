# 测试分层与范围

测试成功只证明相应层级，不代表真实应用、在线服务或发布已经验收。

| 场景 | 入口 | 范围 |
| --- | --- | --- |
| 日常快速反馈 | `tests/verify_development.sh quick` | 发布/CI 契约、安装事务、隐私、源代码边界、词典/翻译 Mock、生产 Host 路由、测试设施负向自测；不跑全部 Swift/原生矩阵 |
| 提交前全量核心 | `tests/verify_development.sh full`（兼容名 `core`） | quick 范围，加全部 Swift/候选外观、英文投影、原生默认矩阵和六项不重复专项 |
| 已构建 App | `tests/verify_development.sh app` | 当前 local-build 的新鲜度、身份、资源、隔离和隐私；不模拟真实输入应用 |
| 发布前自动化 | 先 `make release`，再 `tests/verify_development.sh release` | full + App + 严格 SwiftLint + Periphery + 覆盖率退化门；不签名、安装、上传或真实联网 |
| 真实验收 | [验收清单](ZIME-ACCEPTANCE.md) | 独立桌面 Settings 点击、真实 API、跨系统/应用、双屏截图及长时使用；需要对应环境和明确授权 |

原有 `all` 仍是 full + App（不含 lint/Periphery/覆盖率）。`swift`、`rime` 是定向分组。
依赖必须先按锁文件准备，快速测试也不是无依赖检查。无环境/权限的测试应写
`NOT_EXERCISED`，不能伪装通过或在日常桌面绕过隔离保护。

## 重复与缓存

- 默认原生矩阵已包含数字混输，完整入口不再额外跑同一 `--zime-alphanumeric-probe`；
  单项参数仍供诊断。其余快捷键、双语学习、大小写、分页、方案按键矩阵和压力专项保留。
- Settings 投影和 C++ harness 只缓存**编译产物**，每次仍执行测试，且使用独立 UserData。
  C++ 缓存校验编译器版本、选项、源码、各编译单元的传递头文件、SDK 头、链接库和产物摘要；
  每次先重新预处理并比较当前依赖和预处理结果，以检测新增高优先级头文件及
  `__has_include` 条件变化。输入缺失/变化或产物损坏会重新编译，编译失败不能使用旧产物。
  并发写入有锁；命中不再等于免除预处理，其耗时与编译耗时分别看待。
- Swift/C++ 共享按编译命令加锁的产物存储；依赖解析、完整性检查、发布和输出复制
  都在锁内，每次编译使用独立暂存目录。编译后再次核验输入，拒绝编译期间变化。
  Swift 每次查询重算源文件、包含路径、桥接头文件和链接库摘要，跟随目录符号链接
  并防止递归环；编译环境与辅助脚本也参与失效判断。
  编译失败在 shell 条件调用中也必须传播；强制终止遗留的自建暂存目录在下次取得
  同一把锁后回收，不跟随外部符号链接。
- 翻译用例复用上述编译边界；翻译和 Host 路由执行文件使用各自独立的临时目录，
  结束时清理，不再并发写入同一个 `build/zime-tests` 可执行文件或提取源码。
- golden 探针、部署和编译使用同一子进程管理器：持续排空 stdout/stderr、分块写入
  stdin，以单调时钟管理期限，超时向自建进程组发送 TERM/KILL 并回收直接子进程。
  不使用会在清理阶段继续等待子进程的 `Timeout.timeout { Open3.capture3 }`。
- 插桩覆盖率与普通行为测试不是同一次执行，故保留。CI 开头的廉价发布权限检查用于
  在依赖构建前尽早失败，核心入口仍独立检查，不以环境变量“已验证”绕过它。
- 8 方案 golden、按键矩阵、历史数据迁移覆盖不同职责，不为了耗时合并或删除。
- 历史无效脚本见 [归档说明](../tests/legacy/README.md)。`verify_zime_upstream.sh` 和
  `verify_zime_upstream_matrix.sh` 用于上游变更专项，不是每次提交必跑的日常门。

## 覆盖率门

`tests/verify_zime_coverage.sh` 生成 LLVM JSON、文本和 HTML，并执行
`tests/zime_coverage_policy.json` 的门槛。基线来自本机 0.1.22 的实际插桩结果，
行/函数百分比向下取至一位小数，另保留已覆盖函数数量下限。

| 被测核心模块 | 行覆盖下限 | 函数覆盖下限 | 已覆盖函数下限 |
| --- | ---: | ---: | ---: |
| 本地词典 | 98.5% | 93.1% | 108 |
| 候选翻译 | 95.1% | 83.3% | 30 |
| 安装事务 | 93.9% | 95.2% | 20 |
| 翻译设置模型 | 87.8% | 83.3% | 30 |
| 在线翻译边界（离线 URLProtocol） | 75.5% | 67.3% | 35 |

测量范围固定为 13 个生产文件，缺失、重复、额外文件或损坏计数直接失败。
其余依赖文件只报告，不把这套夹具中的低覆盖率误当作整个项目未测试。
目前没有全项目覆盖率，也没有 Swift 分支覆盖率。不得为了通过测试自动降低门槛；
必要的生产代码删减/范围调整须说明原因，并一起审查策略与测试。
门本身有退化、删除测试、范围变化和损坏报告的负向用例。

Host 测试直接编译完整双语 extension，并按 Swift 语法选出真实 RimeSession 类型、
选词和翻页函数。不会复制业务实现；重排/换行/注释允许，缺失或重复声明拒绝。
IMK 客户端及 Rime 副作用由夹具代替，因此不冒充真实输入应用 E2E。

## 防止漏检的回归用例

- 基础设施：`verify_test_process.rb` 覆盖双向大数据、早关 stdin、超时、忽略 TERM、
  后代保留管道、输出上限和描述符回收；`verify_compile_artifact_cache.rb` 覆盖并发锁、
  不同输入的产物隔离、错误清单、产物损坏、输入中途变化、符号链接和编译中断恢复；
  `verify_swift_test_cache.rb` 使用真实 Swift 编译器验证命中、头文件变化、符号链接、
  新增文件、环境包含路径与编译选项。这些测试属于 quick/full/release 共用门。
- C++ 缓存：覆盖头文件新增/删除导致的搜索优先级变化，以及不实际 include 的
  `__has_include` 分支；同时保留多编译单元、缺失输入、损坏产物和选项变化测试。
- 发布工作流：必须在打包/上传前完成 core、App、Settings UI、SwiftLint、Periphery、
  覆盖率和发布权限检查。校验器对必要步骤被删除、跳过、容忍失败、仅 echo 或短路，
  以及先打包/上传后检查的情况执行负向测试。
- Host 原文回车：先填充源快照和译文列表，再验证取消、快照清空、列表清空，
  以及 Tab 不能重新打开旧候选。迟到响应不刷新旧输入由候选翻译器测试覆盖。
- HTTP：`ZIMETranslationHTTPTests.swift` 通过会话工厂注入 URLProtocol；生产请求构造、
  URLSession 执行、禁止重定向委托、流式字节限制和解析都不替换。覆盖四家服务、
  非成功状态、非 HTTP 响应、超时/断网错误传播、无效 JSON、64 KiB 边界及请求取消。
  超限响应不结束流，确保不能靠完整缓冲后的解析检查蒙混通过。请求全部拦截，
  取消前分别确认“未收到响应头”和“已收到响应头及部分正文”，并按当前请求记录
  stopLoading，防止上一请求迟到事件冒充本次取消成功。无效 JSON 和有效 JSON
  缺译文字段分别检查解析错误与响应错误，不接受任意错误就算通过。
  使用合成凭据，不读取钥匙串、不创建网络连接；真实服务兼容性仍需显式在线验收。
- 候选翻译：迟到响应使用测试主动释放的 continuation，先等请求进入，再取消输入，
  最后释放旧响应并断言没有刷新。成功/失败及来源标签等待刷新事件，不与固定睡眠竞速；
  不请求类检查仍跨越实际 debounce/rate-limit 观察窗口，并有总期限保护。
