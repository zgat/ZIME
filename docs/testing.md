# 测试分层与范围

测试成功只证明相应层级，不代表真实应用、在线服务或发布已经验收。

| 场景 | 入口 | 范围 |
| --- | --- | --- |
| 日常快速反馈 | `tests/verify_development.sh quick` | 发布/CI 契约、安装事务、隐私、源代码边界、词典/翻译 Mock、生产 Host 路由、测试设施负向自测；不跑全部 Swift/原生矩阵 |
| 提交前全量核心 | `tests/verify_development.sh full`（兼容名 `core`） | quick 范围，加全部 Swift/候选外观、英文投影、原生默认矩阵和六项不重复专项 |
| 已构建 App | `tests/verify_development.sh app` | 当前 local-build 的新鲜度、身份、资源、隔离和隐私；不模拟真实输入应用 |
| 发布前自动化 | 先 `make release`，再 `tests/verify_development.sh release` | full + App + 严格 SwiftLint + Periphery + 覆盖率退化门；不签名、安装、上传或真实联网 |
| 真实验收 | [验收清单](ZIME-ACCEPTANCE.md) | 独立桌面 Settings 点击、真实 API、跨系统/应用、双屏截图及长时使用；需要对应环境和明确授权 |

原有 `all` 仍是 full + App（不含 lint/Periphery/覆盖率）。`swift`、`rime` 是定向分组。
依赖必须先按锁文件准备，快速测试也不是无依赖检查。无环境/权限的测试应写
`NOT_EXERCISED`，不能伪装通过或在日常桌面绕过隔离保护。

## 重复与缓存

- 默认原生矩阵已包含数字混输，完整入口不再额外跑同一 `--zime-alphanumeric-probe`；
  单项参数仍供诊断。其余快捷键、双语学习、大小写、分页、方案按键矩阵和压力专项保留。
- Settings 投影和 C++ harness 只缓存**编译产物**，每次仍执行测试，且使用独立 UserData。
  C++ 缓存校验编译器版本、选项、源码、各编译单元的传递头文件、SDK 头、链接库和产物摘要；
  输入缺失/变化或产物损坏会重新编译，编译失败不能使用旧产物。并发写入有锁。
- 插桩覆盖率与普通行为测试不是同一次执行，故保留。CI 开头的廉价发布权限检查用于
  在依赖构建前尽早失败，核心入口仍独立检查，不以环境变量“已验证”绕过它。
- 8 方案 golden、按键矩阵、历史数据迁移覆盖不同职责，不为了耗时合并或删除。
- 历史无效脚本见 [归档说明](../tests/legacy/README.md)。`verify_zime_upstream.sh` 和
  `verify_zime_upstream_matrix.sh` 用于上游变更专项，不是每次提交必跑的日常门。

## 覆盖率门

`tests/verify_zime_coverage.sh` 生成 LLVM JSON、文本和 HTML，并执行
`tests/zime_coverage_policy.json` 的门槛。基线来自本机 0.1.22 的实际插桩结果，
行/函数百分比向下取至一位小数，另保留已覆盖函数数量下限。

| 被测核心模块 | 行覆盖下限 | 函数覆盖下限 | 已覆盖函数下限 |
| --- | ---: | ---: | ---: |
| 本地词典 | 98.5% | 93.1% | 108 |
| 候选翻译 | 95.1% | 83.3% | 30 |
| 安装事务 | 93.9% | 95.2% | 20 |
| 翻译设置模型 | 87.8% | 83.3% | 30 |
| 在线翻译边界（离线 Mock） | 67.4% | 62.7% | 32 |

测量范围固定为 13 个生产文件，缺失、重复、额外文件或损坏计数直接失败。
其余依赖文件只报告，不把这套夹具中的低覆盖率误当作整个项目未测试。
目前没有全项目覆盖率，也没有 Swift 分支覆盖率。不得为了通过测试自动降低门槛；
必要的生产代码删减/范围调整须说明原因，并一起审查策略与测试。
门本身有退化、删除测试、范围变化和损坏报告的负向用例。

Host 测试直接编译完整双语 extension，并按 Swift 语法选出真实 RimeSession 类型、
选词和翻页函数。不会复制业务实现；重排/换行/注释允许，缺失或重复声明拒绝。
IMK 客户端及 Rime 副作用由夹具代替，因此不冒充真实输入应用 E2E。
