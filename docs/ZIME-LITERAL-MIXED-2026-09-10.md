# 未匹配尾串的整段混输候选

2026-09-10。接续 0.1.18 的英文补全边界修复。

## 问题与规则

0.1.18 已拒绝 `woi → 我IME` 这类过度补全，但 `wov` 仍只显示消费 `wo` 的“我”，
无法像用户提供的 macOS 原生截图一样一次选择“我v”。

本次在中文模式下，没有有效整段候选时，用原生词典候选覆盖的最长前缀加上未匹配的
ASCII 字母尾串生成整段候选。没有自行实现第二套拼音切分，也没有为 `wov` 写特例。

- `wov → 我v`、`woi → 我i`、`woim → 我im`、`nihaov → 你好v`。
- 数字选择一次提交整个候选；回车仍提交输入原文 `wov`。
- 已有的整段拼音、简拼、模糊匹配、英文及完整混输优先沿用原生结果，
  例如 `wox → 我想`、`nh → 你好`、`woime → 我IME`。
- 专用英文模式、显式大写和数字/代码识别路线不变。
- 原生分段候选仍可选择，第一页保留一个入口。生成池最多八项，不遍历无界的后续候选；
  学习排序后才按 3–9 行分页，所以减小行数不会删除已经学习的备选项。

## 数据与实现边界

整段候选使用独立的 `zime_literal_mixed` 类型，起止位置覆盖全部输入，不伪装成较短的
词典词条。复用当前模式下按实际输入记录的选择学习，不另建数据库，不把“我v”学进
`wo` 对应的原生词条。禁用学习时不读写这些偏好。

候选不冒用“我”的译义作为“我v”的完整翻译；本地/在线译文仍通过已有翻译链路查询。
繁简转换只改变中文部分，不改变尾串大小写。原文/译文切换的显式提交语义不变。

全部验证使用隔离数据目录，不修改本机正在使用的学习数据和设置。
