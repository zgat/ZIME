# 2026-09-16 测试工程缺陷修复

交付目标：0.1.22 build 31。本轮修复测试基础设施，并加固翻译设置保存的失败恢复；
不调整候选排序、输入交互或内置词库。不自动推送或发布 GitHub。

## 修复与判错证据

- 嵌套 Ruby 所有者在信号/超时后先协作回收内层，再做强制清理；一层/三层 Ruby、
  CLI 和独立进程组叶子都必须按内到外顺序退出。新增语义变异要求匹配“叶子仍存活”
  的特定断言，任意非零返回不算抓到目标问题。兼容系统 Ruby 2.6。
- 安装脚本禁用命令扫描显式区分匹配、无匹配和扫描器失败。新增实际 shell 用例
  曾在旧实现上失败，修复后四种禁用命令及扫描异常均被拒绝。
- App 新鲜度纳入插件、脚本、工具及完整配置目录。真实 Git 夹具逐类修改文件，
  必须因对应输入比构建新而失败，不能由无关错误代替目标断言。
- 覆盖率记录必须取得有效提交和工作区状态，并验证测量前后的提交一致。
  实际 CLI 负例覆盖 Git 失败、空/无效/不一致 revision；不产生成功摘要。
- 编译缓存输出改为原子替换，拒绝目录、符号链接及缓存文件自身别名，不写穿硬链接。
  竞争用例使用锁握手，在编译、发布两阶段都确认第二请求真实争用同一把锁。
- C++ 间接链接输入暂不复用缓存，真实静态库从值 1 改为 2 后必须得到新程序；
  删除库后的编译失败不得覆盖已有输出。显式 dylib 路径仍参与摘要并可命中。
- CI 契约补充整项 job 跳过和 job 容忍失败负例，三套工作流共 65 个负例。
- 安装事务新增 14 个 Host 中途重启边界：首次/覆盖安装、发布及回滚检查，确认
  已发布范围、备份/中断标记、学习数据及后续拒绝重入。删除关键 guard 的生产副本
  以指定断言失败，证明不是仅执行成功路径。

翻译设置的保存异常属于注入存储回调的契约加固，并非复现了默认钥匙串的数据丢失。
新增凭据快照和补偿恢复；配置失败后恢复替换/删除/新建前状态，恢复失败仍保留
待处理状态，撤销不能显示为已成功。测试仅使用合成凭据，不访问实际钥匙串或网络。

## 精简和成本

运行器/所有者套件只在变异门的三组基线中执行一次，保留独立诊断入口。外层预算
由 30 秒调至 120 秒，避免包含 30 秒编译预算的整个套件共用同一上限。
Swift 桥接头的真实内容依赖仍由编译器报告，父目录只做名称/类型清单；修改无关
文档不再造成 MISS。可选分阶段耗时日志不跳过依赖扫描、不降低缓存正确性要求。

未降低任何覆盖率阈值，未增加生产测试绕过参数。限定模块覆盖率、离线协议用例
不等价于真实服务、独立桌面 Settings、跨应用/双屏和长期使用验收。
