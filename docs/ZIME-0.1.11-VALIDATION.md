# ZIME 0.1.11：通用英文释义大小写查询

日期：2026-09-07。版本 0.1.11 / build 12，arm64，最低目标 macOS 13。

## 根因与通用修复

用户报告 `IME` 有翻译而 `ime` 没有。真实引擎复现表明：释义索引存的是
`m/zh/IME`；小写及混合大小写候选可能属于 raw/forced-raw，原逻辑不为它们
查释义。中文模式 `ime` 还可能来自中文词典的 `IME` 词条，其已有中文释义
没有英文释义标记，Host 会将其当作拼写提示丢弃。

本版没有 `IME` 特判，也没有逐词硬编码替换：

- 构建时从整份现有审校词表自动生成 case-folded → 原始词头的只读索引。
  覆盖当前释义数据库全部 **1,064 个非全小写词头**，包括普通首字母大写词、
  全大写缩写及 `GraphQL`、`AppImage`、`DoH` 等任意混合大小写词头。
  新词随词表生成索引，Make 依赖会触发重建，无需新增单词分支。
- 运行时优先查询精确大小写，再通过统一折叠键和生成索引恢复词典词头。
  二分索引后依旧读取现有 PredictEngine 的定义，不扫描词库，不另开一份
  引擎，不修改已安装语言包。普通全小写词直接查询原索引。
- 已识别的纯英文字母 raw/forced-raw 候选可以获得本地释义，但保留原类型、
  排序、大小写和原样提交路径；代码／URL 不经过这个额外原样词注释分支。
- 中文词库中的英文缩写也获得正确的释义标记，Host 不再将它丢弃。
- 精确词义及明确排除优先，不能把大小写差异导致的不同词义盲目合并：
  `DoH` 保留“基于HTTPS的域名系统”，`doh` 保留原词库“卫生部”；`US`
  不套用 `us` 的代词释义。找不到真实释义时仍显示缺失，不生成假翻译。
- 只改释义查询与注释，不改变学习键或跨模式训练边界；译文仍需先切换
  候选状态、再显式确认才会上屏。没有新增云请求或权限。

## 验证

- `tests/verify_zime_case_aliases.rb` 通过：独立扫描实际生成的释义数据库，
  确认所有 1,064 个非全小写词头都在别名索引内。任意虚构混合大小写词的
  生成测试证明新增词条无需代码特判；重复生成字节相同，排除项不被收录。
- `tests/verify_rime_runtime.sh --zime-case-probe` 通过：真实引擎检查
  **4,255 种词表级大小写变体**，并在中文与独立英文模式下验证实际候选。
  覆盖 `ime/Ime/IME/iMe/iME`、hello/cloud/API 各类大小写，以及 DevOps、
  GraphQL、AppImage、DoH、JavaScript、CPU、GPU 的混合大小写输入。
  注释阶段不提交，显式选词后提交文本与候选原有大小写一致。
- 精确大小写词义优先、专名排除、不复用失败查询的旧结果、关闭释义及
  音标后的隐藏行为均通过。中文模式原有 `ime → IME` 候选拼写保留；
  独立英文的 `ime` 候选和上屏结果仍为小写 `ime`。
- 最终通用索引版本的 `--zime-bilingual-probe` 和 `--zime-shortcuts-probe`
  均通过：中文混排与英文训练继续隔离；Tab 切换、Enter 确认、智能补全
  只改待输入内容的规则不变。
- `tests/verify_zime_translation.sh` 通过，新增本地词库大小写缓存检查与
  Host 注释传递检查，确认各类大小写的原文、候选索引、译文及上屏边界
  不被更改。使用本地字库和 mock transport，没有访问凭证或真实 API。
- `tests/verify_swift_units.sh` 全部通过；Release 构建、产品身份、旧设置
  清理检查、ZIP/PKG 打包、解包和最终 App 严格签名校验通过。

验证边界：本轮未执行用户前台应用的自动输入或完整 XCUITest。旧的完整
Linnet 原生总测试仍受“八种中文方案”遗留断言限制，见 0.1.10 验证记录；
本轮使用上列专项，不宣称该旧总门禁通过。
