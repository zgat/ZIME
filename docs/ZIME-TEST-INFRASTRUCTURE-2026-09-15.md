# 2026-09-15 测试工程再审查

本轮目标：0.1.22 build 26。只修改测试设施与构建号，不改变输入法业务逻辑。

## 已复现问题与修复

1. Swift 旧缓存的二进制、输入摘要、产物摘要分开发布且无锁。受控并发下，要求输出
   `11` 的编译请求会显示缓存命中却执行 `22`。改为 Swift/C++ 共用锁内校验、发布和
   复制边界，独立暂存，编译前后检查依赖一致性。真实 Swift 用例覆盖源文件、目录
   符号链接、桥接头、包含路径与选项；公共用例覆盖并发及中断恢复。强制终止遗留的
   自建暂存目录，在同一命令下次取得锁后回收，回收测试验证不跟随外部符号链接。
   shell 函数显式传播编译失败，补测 `if` 调用关闭 errexit 时不会误报成功。
2. golden 原有 `Timeout.timeout { Open3.capture3 }` 到期后仍等待子进程自然退出。
   改为直接管理自建进程组和非阻塞管道，TERM 后按期限 KILL、回收直接子进程；
   探针、部署及编译都经过此边界。反例同时覆盖忽略 TERM 和后代持有管道。
3. HTTP 两个取消阶段都只等待“请求开始”，即使都不发送响应头仍能通过。
   改为明确检查响应头/部分正文里程碑，取消事件按当前 URLProtocol 实例归属。
   分别将响应头或正文删除的临时变异版本都必须失败；错误响应检查也不再接受任意错误。
4. 翻译与 Host 路由脚本写入固定可执行文件和提取源码，存在并行运行互相覆盖风险。
   复用已有临时目录生命周期管理器，编译缓存仅共享已验证产物，不共享执行工作区。
5. 候选翻译的取消用例依赖固定 450 ms 等待与 150 ms Mock 响应的窄时间窗口。
   改为等待请求进入后主动释放响应，成功/失败/来源标签等待对应刷新事件；撤销
   同意发生在首次 yield 前，避免负载较高时越过 debounce。无请求类断言仍保留
   跨越真实 debounce/rate-limit 的观察窗口，另设总期限。
