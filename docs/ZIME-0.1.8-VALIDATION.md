# ZIME 0.1.8：中英文双向选词学习

日期：2026-09-07。版本 0.1.8 / build 9，arm64，最低目标 macOS 13。

## 原因与修复

0.1.6 的规则保护了中文简拼，但没有完成对称的英文学习：中文模式中
`linnet_english_words/enable_user_dict` 原本为 false，选择英文不写入其
原生用户词库；排序层又将已学习的中文固定优先于英文。隔离测试中连续
选择 `key` 八次后，它仍是 `table`，`commit_count=0`。

- 中文模式启用 Rime 的英文用户词库，与独立英文模式共用 `linnet_en`。
  不新增偏好数据库，不写入不可变的翻译／预测索引。
- 设置投影明确写出两种模式的用户词库和学习开关，使只更新 Core、保留
  旧语言包也能修复。关闭英文学习同时关闭两条英文路径，不关闭中文学习。
- 中文优先／常见英文例外继续作为未学习时的默认规则。对于同一输入范围
  内的完整英文词，使用原生选词计数与中文候选比较：英文超过某个中文词
  的次数后可越过它；次数相同时中文优先。中文内部的原生相对顺序不变，
  不跨越自定义候选或不同输入范围的候选边界。
- 不直接比较中英词库的 `quality` 或 `weight`：它们的计算公式与归一化
  基数不同。沿用已有 64 项有界预取和惰性尾部，未增加同步磁盘查询。

这里的学习是实际选择候选，不是仅输入字母或浏览候选。旧版在中文模式下
未记录的英文次数无法恢复；已有中文词频与独立英文模式的记录继续使用。

## 验证

- `tests/verify_rime_runtime.sh --zime-bilingual-probe` 通过。测试刻意将
  临时语言包改回旧版关闭学习的配置，再用生产设置投影部署，验证升级路径。
- 初始 `key → 可以`、常见英文弱中文匹配例外、大小写显式英文、独立英文
  模式、中文简拼／模糊／混输与仅提交主文本的既有测试继续通过。
- 隔离原生词库：先选“可以”3 次、“科研”6 次，然后逐次选择 `key`：
  1–3 次排在两者之后；4–6 次越过“可以”；第 7 次越过“科研”。
  再将“科研”累计至 10 次，中文回到首位；英文累计至 12 次，英文再次首位。
  英文模式另选一次后，中文模式立即读到同一记录的 13 次。
- 引擎重开及独立新进程均保持英文首位和精确的 13／10 次记录。
  关闭英文学习后，在两种模式各选择 `key` 4 次，均不加载／修改英文
  用户词条；中文仍正常学习。重新开启并启动新进程，原记录仍是 13／10。
- `tests/verify_swift_units.sh` 全部通过，未跳过外观测试。设置投影、
  开关迁移、保存事务、候选窗口和 Local Data 标题点击等均通过。
- 原生分页边界、离线翻译／模拟 API、候选展开代码清理、产品静态校验通过。
- Release 构建、ZIP/PKG 打包与解包后的 App 深度严格签名验证通过。
  本机 Host、Settings 和智能英文插件与最终签名交付 App 逐字节一致。

未向用户前台应用自动输入测试文本，未读取 API 凭证或发送云翻译请求；
不将原生引擎测试等同于人工逐应用输入验收。
