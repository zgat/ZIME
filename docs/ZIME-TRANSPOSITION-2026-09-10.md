# 中文换位纠错与英文候选边界

目标版本：0.1.20 / build 21。接续 0.1.19 的整段混输修复。

## 原因

空白学习记录下，`nui` 同样出现 `niu、nui、你…`。英文 Prism 为三字母提供末尾两字母换位，
中文全拼却未覆盖 `nui → niu`；英文候选消费整段，中文只匹配首字母 `n`，使同跨度中文优先
失效。英文精确候选的提升分支又不会跨越另一条普通英文候选，因此 `niu` 能挡在 `nui` 前。
这不是“牛”的译文错了；两条释义本来属于英文词库的冷门词条。

## 调整

- Core 的设置投影为全拼增加 `derive/^([jqxnlm])iu$/$1ui/`。仅覆盖没有合法 `-ui`
  音节的这些声母，不将合法 `dui/gui/hui/shui/tui` 无差别交换。规则在英文实体小写化之前
  插入一次，不改变双拼；安装时通过原生部署更新 Prism，旧语言包同样生效。
- 按相同输入范围先排列英文精确匹配，再排列别名/补全，不越过中文、用户自定义或分段边界。
- 对英文别名和补全也复用当前模式、当前输入的显示选择学习；完整 `niu` 的选择次数不能
  自动覆盖 `nui` 的偏好。在 `nui` 下主动选择英文、别名或中文仍能双向调整排序。
- 当存在完整中文音节前缀时，冷门英文及英文别名不再阻止生成“中文＋原样尾串”。原生整段
  中文、混输、自定义候选以及常见精确英文仍保留原路线。只有首字母简拼时不触发此放宽。
- 生成池及第一页原生分段入口仍保留；入口通过实际消费范围识别，避免误把英文整段候选
  当作分段入口。没有删词库、禁用英文，或更改原文/译文切换与回车原文提交规则。

## 验证范围

新增原生测试覆盖 `nui/lui/jui/qui/xui/mui`、`nuinai` 词组、3–9 行、emoji 开关、一次数字
上屏、回车原文、退格、繁体、合法 ui 拼音、显式大写、独立英文模式和 `shii → 是i` 的
冷门英文兜底。学习测试包含英文与中文双向升序、别名与精确输入隔离、禁用学习不写入、
中英文模式隔离、跨进程保存。全部使用隔离数据，不读取真实个人词频作为测试输入。
