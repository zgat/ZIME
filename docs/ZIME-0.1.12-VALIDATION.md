# ZIME 0.1.12：字母数字混合原文输入

日期：2026-09-07。版本 0.1.12 / build 13，arm64，最低目标 macOS 13。

## 根因与行为

旧交互层会把没有对应候选的数字返回给前台应用，同时保留待输入字母。
因此每页 5 个候选时输入 `x` 再按 `7`，数字先上屏，之后回车才提交字母，
造成顺序颠倒。原来的原生测试还明确要求这种无效数字透传，本版一并替换。

- 中文与独立英文模式下，字母后没有对应当前页候选的数字并入待输入原文。
  `x7` 形成首位且唯一候选 `x7`，不会提前提交；回车整体上屏一次。
- 已进入字母数字原文后，继续输入数字或字母仍为同一候选，如 `x71a09`。
- 未进入该原文状态时，有效的当前页数字选词保持不变；例如每页 9 个候选、
  确实存在第 7 项时，`7` 仍选第 7 项。`0` 不选择隐藏的第 10 项。
- 只有强制原文候选、没有词典匹配的字母串接受全部数字，包括 `1`。
- 普通数字键与数字键盘一致；删除最后一个数字可恢复字母匹配，Escape
  取消，光标中间插入保持顺序。无待输入内容的数字与应用组合键不变。
- 新分段器位于 Matcher 之后，显式 Unicode、计算器、反查命令优先。
  复用原来的 raw 候选和提交路径，不另建学习库、不发起新网络请求。
- Core 投影发布唯一的新分段器，旧语言包无需替换；不修改真实设置字段、
  用户词频或快捷键。译文仍需先切换候选状态再确认才会上屏。

## 验证

- `tests/verify_rime_runtime.sh --zime-alphanumeric-probe` 通过：两种模式、
  每页 3–9 项、无效数字与 `0`、连续输入、有效选词、数字键盘、删除恢复、
  取消、中间插入、应用组合键、空闲数字、强制原文及 Unicode 命令优先级。
- 原生专项测试将临时语言包中的新分段器移除，再应用生产 Core 投影，
  验证保留旧语言包时依旧正常；Swift 投影测试检查顺序和不重复安装。
- `--zime-bilingual-probe`、`--zime-shortcuts-probe`、`--zime-paging-probe`
  通过：中英文模式学习隔离、显式确认、智能补全及首尾翻页行为不变。
- `--zime-case-probe` 通过，覆盖 1,064 个词头的 4,255 种大小写变体。
  本版包含 0.1.11 的全词表通用大小写释义修复，不仅针对 IME。
- `tests/verify_zime_translation.sh`、完整 `tests/verify_swift_units.sh`、
  Release 构建及 `tests/verify_zime.sh` 产品身份／旧设置清理检查通过。
- ZIP/PKG 打包和内部解包校验通过；从最终 ZIP 独立解出 App 后，严格深度
  签名及产品身份检查再次通过，确认版本为 0.1.12 / build 13。

验证边界：未自动向用户前台应用输入，也未运行完整 XCUITest。旧 Linnet
原生总测试的“八种中文方案”断言仍不适用于 ZIME，见 0.1.10 记录；本轮
使用以上专项，不宣称旧总门禁通过。测试使用隔离临时数据，不清理真实学习。
